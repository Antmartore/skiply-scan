You're building Skiply Scan — a footwear Identify/Grade/Value/Route engine. The repo already contains a working single-file MVP (`index.html`): Face ID-style 3-angle capture, on-device zero-shot CLIP via Transformers.js (`Xenova/clip-vit-base-patch32`), a 55-entry silhouette catalog, valuation formula `MSRP × GradeFactor × BrandDemand × Market`, and a routing tree (RESALE / REPAIR→NuShoe / DONATE→Soles4Souls,Goodwill / RECYCLE). Read `index.html`, `README.md`, and `Skiply_MVP_Build_Plan.md` fully before writing any code.

Hard constraints — these are non-negotiable:
1. Inference stays on-device. No calls to paid inference APIs. Latency budget: scan-to-result under 3s on WebGPU, under 8s on WASM.
2. Keep the app deployable as a static site (GitHub Pages today, Vercel later). No server required for scanning.
3. Preserve the Skiply brand system exactly as in `index.html`: navy void (#04070d), panel #0a111c, line #1b2c44, ink #eef5ff, accents green #3dd98c / cyan #53d7ff / amber #ffb347 / red #ff5d5d / blue #0A64BC, mono data labels, tagline "IDENTIFY · VALUE · ROUTE".
4. Don't break the demo mode or the correction/training-data flow — the pitch depends on them.

Build, in this order, committing after each milestone:

**M1 — Repo hygiene.** Split the single file into `/src` with Vite (vanilla JS, no framework). Output must still build to a static bundle. Add GitHub Actions workflow deploying `dist/` to GitHub Pages on push to main. Verify the live URL works on a phone.

**M2 — True offline (PWA).** Service worker that precaches the app shell AND the ONNX model files after first load, plus a manifest (installable, black theme, Skiply icon from the SVG wordmark in index.html). Acceptance: airplane mode → app opens and scans.

**M3 — Reference image embedding DB (Stage 2 of the build plan).** Create `scripts/build_reference_db.py`: given a folder of product images organized `brand/model/colorway/*.jpg` plus a `products.csv` (brand, model, colorway, year, msrp, demand), embed every image with Marqo/marqo-fashionCLIP (fall back to fashion-clip or CLIP B/32 if ONNX conversion is a blocker), and emit `public/refdb.json` (quantized embeddings + metadata, target <15MB). In the app, load refdb.json when present and match scans against image embeddings instead of text embeddings; keep text zero-shot as fallback. Show colorway + year from the matched reference.

**M4 — Scan telemetry & training export.** Move scan logs from localStorage to IndexedDB, add batch export (JSON + CSV) including captured frames as JPEG blobs in a zip, so corrections become a real training set.

**M5 — Passcode gate (per Zeed's spec).** Optional access mode: single-use 6-character code, valid 1 hour, for client pilots. Static-friendly implementation: codes generated by `scripts/gen_codes.py` as salted hashes shipped in a JSON; client checks hash + expiry locally. Toggle via `?gated=1`.

**M6 — Partner routing config.** Extract routing to `public/routing.json` (channels, partners, thresholds, geography) so NuShoe/Soles4Souls/Goodwill rules are editable without code. Settings panel shows active config.

Quality bar: mobile Safari + Chrome tested (use responsive devtools), Lighthouse PWA pass, no console errors, README updated per milestone. When something is ambiguous, make the call that best serves a live sales demo and note it in the commit message.
